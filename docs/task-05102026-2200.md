## Current Task — Discovery Result Caching

### Objective

Add persistent caching for discovery results so expensive discovery scanners can be skipped when valid cached results exist.

Initial scope:

- IMAP
- OSINT
- BREACH

### Master switch

Use one `.env` switch:

`DISCOVERY_CACHE_ENABLED=false`

### Intended behavior

Cache disabled:

IMAP → OSINT → BREACH → fresh discovery → write/update cache.

Cache enabled + valid cache:

cache check → load valid result → skip expensive scanner.

Cache enabled + miss/invalid/schema mismatch:

cache check → fresh discovery → write/update cache.

### Proposed structure

`cache/discovery/imap.json`
`cache/discovery/osint.json`
`cache/discovery/breach.json`

### Architectural boundary

Discovery cache stores candidate findings plus relevant discovery provenance/metadata.

It must not become final evidence or risk scoring.

Flow remains:

DISCOVERY CACHE → CANDIDATE FINDINGS → EVIDENCE ENRICHMENT → EVIDENCE → SCORING / POLICY

### Required audit before patch

Audit the complete call-chain:

IMAP entry → caller → scanner → result/state → OSINT → BREACH → pipeline → existing cache mechanisms → error/fallback paths.

Do not implement this as a simple wrapper or search/replace.

Existing Breach cache behavior and existing AI/evidence cache conventions must be inspected so the new discovery cache does not duplicate or conflict with them.

### Definition of Done

- `DISCOVERY_CACHE_ENABLED` implemented and documented in the appropriate configuration surface.
- Cache hit logged explicitly.
- Cache miss logged explicitly.
- Invalid/schema-mismatch cache falls back to fresh discovery.
- Fresh discovery writes/updates cache.
- Cache-disabled behavior remains equivalent to the current fresh-scan path.
- IMAP, OSINT, and Breach semantics remain intact.
- NO FINDING, ENGINE FAILED, and RATE LIMITED semantics remain intact.
- Integration tests cover hit, miss, invalid cache, and fresh-write paths.
- Real local test completed.
- Task marked PASS only after real validation.

## Discovery Result Caching — implementation started

Implemented on this task branch:
- Added `services/discovery_cache.py` for encrypted, tenant-bound discovery-result persistence.
- Added `DISCOVERY_CACHE_ENABLED=false` master switch and `DISCOVERY_CACHE_DIR=cache/discovery` to `.env.example`.
- IMAP and OSINT now use the master switch:
  - OFF: fresh scanner execution, then cache refresh.
  - ON: valid cache HIT skips the scanner.
  - ON + cache MISS/invalid/schema mismatch: fresh scan, then cache refresh.
- Breach keeps its existing encrypted cache implementation; the master switch controls whether the pipeline permits cache reuse by passing `force_refresh=True` when the master switch is OFF.
- Discovery cache uses the existing encrypted cache/security primitives and HMAC-based target identity; raw target values are not used as filenames.
- Discovery cache participates in startup retention cleanup and explicit cache clearing.
- Added integration coverage in `tests/test_discovery_cache.py` for default-off behavior, encrypted round-trip, schema rejection, OSINT cache HIT, and OFF-mode refresh.
- No change to Evidence Enrichment semantics: discovery cache remains candidate discovery state, upstream of EvidenceRecord normalization.
