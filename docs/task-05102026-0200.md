## Completed — Discovery Result Caching

### What was done

- Added persistent encrypted discovery-result caching in `services/discovery_cache.py`.
- Added tenant-bound cache identity using HMAC-based target identity.
- Added schema-version validation and TTL handling.
- Added master switch:
  - `DISCOVERY_CACHE_ENABLED=false`
- Added configurable cache directory:
  - `DISCOVERY_CACHE_DIR=cache/discovery`
- IMAP and OSINT use the discovery-cache master switch:
  - OFF → execute fresh scanner, then refresh cache.
  - ON + valid cache HIT → load cached result and skip expensive scanner.
  - ON + MISS/invalid/schema mismatch → execute fresh scanner, then refresh cache.
- Breach retains its existing encrypted breach-cache implementation. The discovery master switch controls whether the pipeline permits breach-cache reuse.
- Discovery cache participates in retention cleanup and explicit cache clearing.
- Discovery cache remains upstream candidate state and does not cross the EvidenceRecord boundary.
- Added integration coverage for cache default-off behavior, encrypted round-trip, schema rejection, OSINT cache HIT, and OFF-mode refresh.

### Architectural boundary

The cache stores discovery state only:

DISCOVERY CACHE → CANDIDATE FINDINGS → EVIDENCE ENRICHMENT → EVIDENCE → SCORING / POLICY

It does not become final evidence and does not participate directly in risk scoring.
